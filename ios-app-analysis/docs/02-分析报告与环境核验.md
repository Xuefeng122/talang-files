**不可用（Windows 平台限制）**

| 能力 | 结论 |
| --- | --- |
| `binary_overview` | 所有后端拒绝：Ghidra 未设置 `GHIDRA_INSTALL_DIR`；Hopper 不支持 win32；IDA 未配置 `REA_IDA_MCP_CONFIG`；Kuna 未设置 `REA_KUNA_COMMAND` |

## 四、Theos 编译链路核验

| 检查项 | 结果 |
| --- | --- |
| `C:\theos\theos` 仓库 | 存在，`git submodule` 已拉起 dm.pl / include / lib / logos / nic / orion |
| `iPhoneOS16.5.sdk` | 存在 |
| LLVM clang | `C:\Program Files\LLVM\bin\clang.exe` |
| Strawberry perl | 存在 |
| GnuWin32 make | 存在（Windows 原生） |
| `ldid` / iOS 交叉链接器 | 缺失 |
| WSL Ubuntu 24.04.3 | 存在，但无 Theos / make / clang / ldid / dpkg-deb |

编译尝试与报错演进：

1. 默认 `THEOS=/c/theos/theos` → `common.mk` 内 `THEOS_MAKE_PATH := $(THEOS)/makefiles` 展开成 POSIX 路径，GnuWin32 make 找不到 `vercmp.mk` / `target.mk` / `legacy.mk`
2. 显式传 `THEOS=C:/theos/theos THEOS_MAKE_PATH=… THEOS_BIN_PATH=…` → 路径问题解决，但报
   `The "iphone" target is not supported on the "" platform`：`$(shell uname -s)` 在原生 make 下取不到平台值
3. 即使平台值补上，仍缺 `ldid` 与 arm64 Mach-O 链接器，无法产出可安装的 `.deb`

结论：**本机 Windows 原生链路编不出 iOS 插件**。源码骨架本身是标准 Theos 工程，换到 macOS / Linux / 配好工具链的 WSL 后可直接 `make package`。

### 源码正确性验证（不依赖链接器）

虽然整机编译走不通，源码本身已用两段更轻的方式验证过：

1. **Logos 预处理**：`perl $THEOS/bin/logos.pl Tweak.x` 退出码 0，生成 86 行 Objective-C。产物里能确认
   `MSHookMessageEx(...viewDidAppear:...)`、`class_addMethod(... rk_dismissResearchPanel:, 编码 "v@:@")`、`class_addProperty("rk_panel")`
   以及 `__attribute__((constructor))` 初始化函数，说明 `%hook` / `%new` / `%property` / `%group` / `%ctor` 全部展开正确。
2. **clang 前端语法检查**：对生成的 `.m` 与 `RKPanel.m` / `RKSettings.m` 执行
   `clang -fsyntax-only -fobjc-arc -target arm64-apple-ios16.5 -isysroot iPhoneOS16.5.sdk`，
   **零错误零警告**。

也就是说，代码在语法与 Logos 展开层面是可编译的；缺的只是 Windows 侧的 arm64 Mach-O 链接器、`ldid` 与打包环节。
